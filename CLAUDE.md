# Lit Talk — agent guide

A lightweight, embeddable comment system that uses **GitHub Issues** as the
backend, shipped as a single **Lit web component** (`<lit-talk>`). Published to
npm as `lit-talk`.

## What this is (and isn't)

- **Is**: a framework-agnostic Custom Element. Drop into plain HTML, React,
  Vue, Svelte — anything that renders HTML. The README's "Zero framework
  lock-in" promise is a hard constraint.
- **Is not**: a React library. Do not pull in React-based UI kits
  (`@quietbuildlab/ui`, MUI, etc.) — they would force every consumer to bundle
  React just to render a comment box.

## Tech stack

- **Lit 3** (`lit`, `@customElement`) — the only rendering framework.
- **TypeScript** with `strict`, `noUnusedLocals`, `noUnusedParameters`,
  `noImplicitAny`, `noImplicitOverride`.
- **No event bus.** Child-to-parent signalling uses native `CustomEvent`
  with `{bubbles: true, composed: true}`. The only declared custom event is
  `comment-added` (dispatched by `<comment-box>` on successful post, listened
  to by `<lit-talk>` via `@comment-added`). No mitt, no module-level
  emitter — multi-instance safety is structural.
- **No HTTP client.** All network calls are plain `fetch()` wrapped in async
  functions in `src/github/api.ts`. No axios, no Effect — we want a small
  bundle and zero CVE surface beyond what the platform gives us.
- **Rollup** for the browser bundle (`lit-talk.bundle.js`), **tsc** for the
  ESM/types package output in `dist/`.

## Layout

```
worker/                             # Cloudflare Worker OAuth proxy (separate deploy; see worker/README.md)
src/
  lit-talk.ts                       # <lit-talk> custom element (orchestrator)
  constant.ts                       # storage keys + default avatar URL
  lib/navigate.ts                   # window.location.assign seam (excluded from coverage)
  github/
    github-apis.ts                  # base URLs (no logic)
    api.ts                          # async fetch wrappers (postComment, fetchUserInfo, etc.)
    types.ts                        # GitHubIssueData, GitHubUser, GitHubComment, GitHubErrorResponse
  components/
    comment-box/
      comment-box.ts                # <comment-box> — textarea + login/post buttons
      comment-box.template.ts       # html`` template (ctx: CommentBox)
      comment-box.styles.ts         # css`` styles for comment-box
    comment-list/comment-list.ts    # <comment-list> — renders comments
```

`<lit-talk>` owns auth + data fetching; it passes `options`, `githubUser`,
`issueData`, and `commentLists` down as Lit `@property` bindings.

## OAuth + comment flow (one paragraph)

`<lit-talk>` reads `?code=...&state=...` on connect → verifies the `state`
against `sessionStorage` (**fail closed**: missing OR mismatched aborts) →
POSTs `{ code, client_id }` to the consumer's `proxy` → expects
`{ access_token }` back → stores it in `localStorage` and emits
`TOKEN_READY` → loads `/user`, looks up the issue by labels
`[label, postUniqueId]`, creates one if missing (with `response.ok` +
payload-shape validation), then fetches comments. New comments post via
`<comment-box>` and trigger `COMMENT_ADDED` to refresh the list.

## Security invariants — do not break

1. **`client_secret` MUST NOT touch the browser.** The interface field is
   deprecated; the proxy holds it server-side. If you reintroduce it in any
   network request, you've reopened a credential-leak vector.
2. **OAuth `state` is fail-closed.** Any callback whose state is missing from
   `sessionStorage` or doesn't match must abort. Do not weaken this to a
   warning.
3. **Bad-credentials responses must clear `accessToken` + `githubUser`** and
   surface to `this.error` — don't write the error body into `commentLists`
   or `theIssueData`.

## Gotchas

- **`replaceState` after OAuth must preserve `window.location.hash`** —
  consumers may use hash-based routing.
- **GitHub `issues?labels=` returns ALL issues matching every label.** Code
  uses `[0]`; that's intentional, but always guard `Array.isArray(data)`
  first since 401/403 returns `{ message: ... }`, not an array.
- **`comment.user` can be `null`** (deleted/ghost users). Always null-guard
  before reading `login`/`avatar_url`/`html_url`.
- **lit-analyzer warns about `<comment-box>` / `<comment-list>` "missing
  imports"** — these are side-effect imports at the top of `lit-talk.ts`.
  Warning is benign.

## Conventions

- **Types over `any`.** New API responses → add a type to `src/github/types.ts`.
- **All network calls live in `src/github/api.ts`** as plain async functions
  returning `Promise<Response>`. Do not call `fetch` directly from components.
- **Components are dumb.** `<lit-talk>` orchestrates state; child components
  only render and emit user events.
- **Don't add inline `console.log` to happy paths.** Keep `console.error`
  for genuine errors only.
- **Match existing style** (single quotes, 2-space indent, trailing commas).
  Prettier config at `.prettierrc.json`.

## Release process

Publishing is automated via `.github/workflows/publish.yml`:

1. Bump `version` in `package.json` and commit.
2. Create a GitHub **Release** with tag `vX.Y.Z` (must match the package.json
   version exactly — the workflow's version-check step fails otherwise).
3. The workflow runs tests (gated at 100% coverage), executes `prepublishOnly`
   (clean → tsc → rollup), and publishes to npm with **provenance**
   attestations (sigstore via GitHub OIDC).

Requires the `NPM_TOKEN` repository secret — a Granular Access Token with
"Read and write" permission on the `lit-talk` package.

`.github/workflows/ci.yml` runs on every push/PR to `main`: typecheck,
lit-analyzer, tests, coverage artifact upload.

## Known issues / follow-ups

- **ESLint v9 config migration**: `.eslintrc.json` is no longer read; needs an
  `eslint.config.js`. The `lint:eslint` script fails.
- **No tests** in `src/` despite `@web/test-runner` (`wtr`) being configured.
- **Access token in `localStorage`** — XSS-readable. Acceptable trade-off
  given the framework-agnostic scope; a backend session would require shape
  the consumer hasn't opted into.

## When making changes

- Run `pnpm run build` and confirm strict TypeScript passes.
- Run `pnpm run lint:lit-analyzer` (ignore the two pre-existing
  no-missing-import warnings on `<comment-box>` / `<comment-list>`).
- If you touch the OAuth flow, the issue-create flow, or `commentLists`
  assignment, re-read the "Security invariants" section above.
- Keep diffs surgical — every changed line should trace to the task.
